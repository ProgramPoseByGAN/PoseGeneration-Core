# 元宇宙数字人人体姿态生成项目：Unity Humanoid 骨骼规范 V1.1

## 一、 规范总览

本规范定义了项目内部使用的标准人体骨骼架构。**
其核心目标是：作为桥梁，无缝连接AMASS数据集、PyTorch深度学习模型与Unity渲染引擎。**骨架设计首要遵循Unity Humanoid
Avatar系统的标准，确保生成的动画能无需手动重定向直接驱动Unity中的角色模型。

本规范是项目数据预处理、模型训练与动画生成环节的唯一骨骼标准，所有模块必须严格遵循。

## 三、 骨骼详规

### 1. Hips

人体部位：盆骨区域。人体重心的近似位置，连接脊柱与双腿。

AMASS映射：直接对应根关节 `pelvis` (索引0)。其全局平移数据 (`trans`) 直接赋予此关节。

Unity Humanoid映射：`Hips`。这是Avatar系统识别的根节点，是运动重定向的基准。

生物合理性扭曲范围：作为根节点，其旋转（尤其是绕垂直轴的旋转）代表整个躯干的转向，范围理论上可超过 **[-180, 180]**
度。但在预处理时，通常会对连续旋转进行“解缠绕”处理，确保数据连续性。

#### **重要描述：所有动画数据的第0帧，必须将此关节的局部旋转设置为 (0, 0, 0)，并作为整个骨架的初始姿态（T-Pose或A-Pose）的参考点。

**

```
项目所用变量名：Hips
```

### 2. LeftUpperLeg

人体部位：左大腿，连接左髋关节与左膝关节。

AMASS映射：直接对应 `left_hip` (索引1)。

Unity Humanoid映射：`LeftUpperLeg`。

生物合理性扭曲范围：**前屈 [0, 120]度；后伸 [0, 30]度；外展/内收 [-45, 45]度；内外旋 [-40, 40]度。**

#### **重要描述：需特别注意髋关节的内旋/外旋角度，不合理的值会导致“拧麻花”式的失真姿态。**

```
项目所用变量名：LeftUpperLeg
```

Unity Humanoid映射：`RightUpperLeg`。

#### 生物合理性扭曲范围：同 LeftUpperLeg，范围对称。

```
项目所用变量名：RightUpperLeg
```

### 4. Spine

```
项目所用变量名：Spine
```

### 5. LeftLowerLeg

人体部位：左小腿，连接左膝关节与左踝关节。

Unity Humanoid映射：`LeftLowerLeg`。

#### 生物合理性扭曲范围：主要运动为屈伸 [0, 150]度（0度为伸直）。膝盖几乎不能后弯（过伸），正常范围不超过 [0, 10]度。

#### 重要描述：在损失函数中必须对超过此范围的角度施加严厉惩罚，这是生成合理动作的关键。

```
项目所用变量名：LeftLowerLeg
```

### 10. Spine2

人体部位：上胸腔与颈根部，是连接躯干与头颈的关键过渡区。

AMASS映射：*融合映射*。采用源 `spine3` (索引9) 与 `neck` (索引12) 旋转的加权平均（如球面线性插值）。这能使胸颈连接处的运动更平滑自然。

Unity Humanoid映射：`UpperChest`（若模型支持）。*此节点增强了上半身动画的表现力*。

#### 生物合理性扭曲范围：与 Spine1 类似但更受限，主要贡献于细微的躯干姿态和呼吸感。

```
项目所用变量名：Spine2
```

### 11. LeftToes

人体部位：左脚趾（在简化模型中代表前脚掌）。

AMASS映射：*新建关节。AMASS/SMPL模型无独立脚趾关节。*

Unity Humanoid映射：`LeftToes`。**Unity依赖此关节判断脚部是否完全着地**，对根运动（Root Motion）和动画混合至关重要。

#### 生物合理性扭曲范围：主要为绕脚踝轴的屈伸，约 [-15, 30]度。

#### 重要描述：必须在BVH文件头中定义其初始 OFFSET，建议值为 (0, 0, 0.1)，指向脚尖前方。其旋转数据可设定为与 LeftFoot 保持固定比例或简单继承，用于模拟蹬地动作。

```
项目所用变量名：LeftToes
```

## 四、 核心实施要求总结
#### 数据流向：`AMASS 24关节` -> `（按本规范映射与处理）` -> `本项目22关节标准数据` -> `PyTorch模型训练与生成` -> `BVH文件` -> `Unity Humanoid Avatar`。

#### 变量名统一：所有环节（Python预处理、PyTorch模型、C# Unity脚本）必须使用本规范第三部分定义的变量名进行标识和关联。

#### 兼容性保障：BVH文件骨骼名称、层级关系必须与本规范完全一致，旋转顺序建议使用 ZXY，单位为度。初始姿态应为标准的T-Pose或A-Pose。

#### 生物合理性约束：在模型训练阶段，应利用第三节中定义的“生物合理性扭曲范围”构建损失函数（如L2损失），对生成的姿态进行物理约束，这是产出高质量、可用动作的关键。

#### 验证：生成的BVH文件必须通过 Blender导入预览 和 Unity Humanoid Avatar驱动测试 双重验证，方可视为本规范实施成功。
